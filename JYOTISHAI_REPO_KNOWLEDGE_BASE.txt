What the product does
---------------------
JyotishAI is a Vedic-astrology career and education intelligence platform. A logged-in
user creates up to four birth profiles. At profile creation the API computes a
consolidated sidereal chart (PyJHora / Swiss Ephemeris) plus KP, Jaimini,
Panchanga, Ashtakavarga, Shadbala, Vimshottari, and extra vargas (D10/D16/D24/
D60/D81). Later pages run domain engines on that consolidated JSON:

  - PUC (ages 15-17): Science / Commerce / Humanities stream determination
  - UG (adult / undergrad): ranked vocational fields (~198 registry branches
    plus 7 synthetic aliases = 205 affinity/ontology keys)
  - Job Timeline: Vimshottari antardasha career windows + optional LLM HTML
  - Business Prediction: entrepreneurship vs employment, sectors, timing
  - Prashna (horary): question-moment chart, no birth data required
  - Chart viewers: South-Indian D1-D81, KP, KN Rao/Jaimini, Parashari strength

Core doctrine (do not silently change)
---------------------------------------
Declared ayanamsha for the SCORING engines: KP_KRISHNAMURTI
  Source of truth: jyotish/llm_policy.py (AYANAMSHA = "KP_KRISHNAMURTI")
  Swiss mode: swe.SIDM_KRISHNAMURTI
Consolidated API export also uses KP ayanamsa + true nodes + 7-karaka Jaimini
  (api/extended.py compute_consolidated).
UI profile form default ayanamsa option is LAHIRI for PyJHora chart drawing
  (frontend ProfileWizard AYANAMSA_OPTIONS). Chart DRAWING and ENGINE SCORING
  are not the same layer. Drawing uses BirthChartBody.ayanamsa (default
  LAHIRI in api/main.py). Scoring engines parse consolidated JSON which is
  produced with KP-oriented consolidated export.
House systems are method-specific, not global. See
  jyotish/llm_policy.py HOUSE_SYSTEM_BY_METHOD.
Default nodes for the HTTP chart API: MEAN nodes (true nodes require full
  Swiss sepl*.se1 files). See api/jhora_bootstrap.py.

Layering rule
-------------
UI never scores a chart. Frontend only:
  - collects birth/career inputs
  - stores a ChartSession in sessionStorage (zustand persist)
  - calls FastAPI
  - renders JSON reports in React (no server-rendered engine HTML for UG/PUC
    in the web app; CLI engines can still write HTML files)

Python engines never talk to DynamoDB. Persistence is only in api/db/*.

LLM rule
----------
LLM is explanation / narrative / selection-labeling, not a scorer.
jyotish/engine.py run_engine() is deterministic by default (enable_llm=False).
UG report narratives are forced on for API via force_llm_report=True in
Job_Career/career_field_report_v2.py build_career_field_report_from_chart().
API stamps student_context.external_llm_consent=True in api/llm_policy.py
prepare_chart_for_api_llm() so HTTP routes always attempt LLM where wired.
If keys are missing, engines must fall back to deterministic placeholder text.

5. DATA STORES (DYNAMODB CONTRACTS)
================================================================================

Region: ap-south-1. Billing: PAY_PER_REQUEST in create scripts.
Floats must be Decimal on write (helpers in each repository).

5.1 JyotishUsers   env DYNAMODB_USERS_TABLE_NAME
    Client: api/db/users_dynamo.py
    Repo:   api/db/auth_repository.py
    Create: scripts/create-jyotish-users-table.sh
    Keys: PK (HASH), SK (RANGE)
    GSI: by_email (email), by_username (username)
    TTL attribute: ttl (OTP rows)
    Entity patterns (see auth_repository):
      USER#{user_id} / PROFILE     user record, bcrypt password
      EMAIL#{email}  / OTP#{purpose} hashed OTP challenge
    Public user fields: user_id, email, username, created_at
    Passwords: bcrypt. OTP: HMAC-SHA256 with AUTH_OTP_PEPPER.

5.2 JyotishProfiles  env DYNAMODB_PROFILES_TABLE_NAME
    Client: api/db/profiles_dynamo.py
    Repo:   api/db/profiles_repository.py
    MAX_PROFILES_PER_USER = 4
    PK = USER#{auth_user_id}
    One logical profile = multiple items (400KB item limit):
      SK PROFILE#{id}                    header: name, birth_input,
                                          user_info, student_context,
                                          career_context, timestamps
      PROFILE#{id}#CHARTS                 d1_table, divisional_charts
      PROFILE#{id}#ANALYSIS#KP
      PROFILE#{id}#ANALYSIS#JAIMINI
      PROFILE#{id}#ANALYSIS#EXTENDED        panchanga, ashtakavarga,
                                          shadbala, vimshottari,
                                          divisional_extended
      PROFILE#{id}#ANALYSIS#CONSOLIDATED   consolidated chart JSON
      PROFILE#{id}#CONTEXT#CAREER           career_timeline JSON
      PROFILE#{id}#CONTEXT#BUSINESS         business_prediction JSON
      PROFILE#{id}#CONTEXT#PUC             puc_analysis JSON
    profile_key uniqueness: normalized name + lat/lon + dob
      build_profile_key() in profiles_repository.py
    Writes at create: compute_profile_sections() then save_profile()
    Later analyses: upsert_profile_section() for CAREER/BUSINESS/PUC
    Education analysis is NOT stored here (own table).

5.3 JyotishEducationAnalysis  env DYNAMODB_EDUCATION_TABLE_NAME
    Client: api/db/education_dynamo.py
    Repo:   api/db/education_repository.py
    Create: scripts/create-jyotish-education-table.sh
    PK: profile_id
    GSI by_user on user_id
    Four gzip+base64 blobs because results ~660KB:
      results_gz, macro_clusters_gz, report_gz, chart_facts_gz
    Heavy per-row keys stripped before save (_HEAVY_ROW_KEYS):
      method_breakdown, registry_v12, ontology_v12, tier_decision_trace,
      step9_convergence, publication_ranking_adjustments, defensibility,
      confidence_dimensions, jaimini_chara_dasha_timing,
      exact_field_contract, curriculum, competency,
      explainability_matrix, confidence_matrix, ...
    Cache policy: compute ONCE. refresh=true is IGNORED if a row exists.
    To recompute: DELETE /api/profiles/{id}/education-analysis first.
    Reason: LLM non-determinism must not silently change stored advice.

5.4 PyJHoraBirthCharts  env DYNAMODB_TABLE_NAME
    Client: api/db/dynamo.py
    Repo:   api/db/repository.py
    Legacy chart snapshots from POST /api/users/{user_id}/charts
    Not the same as authenticated profiles. Frontend pipeline can skip
    persist with VITE_SKIP_CHART_PERSIST or when Dynamo is unconfigured.

If a table env var is missing: DynamoDBNotConfiguredError -> HTTP 503.

26. IMPLEMENTATION PATTERNS AND GOTCHAS
================================================================================

Circular imports
  jyotish.engine imports jyotish_ug.field_methods
  jyotish_ug.runner lazy-imports Job_Career.career_field_report_v2
  which imports run_engine. Do not add eager imports that close the loop.
  jyotish/__init__.py does not import Prashna for the same reason.

Duplicate modules (know which is LIVE)
  Field_Determination/education_engine.py  vs  jyotish_ug/education_engine.py
    CLI leftovers. API uses jyotish_ug.runner + career_field_report_v2.
  Field_Determination/field_methods historically moved to
    packages/jyotish-ug-fields/src/jyotish_ug/field_methods/
  competency_ontology lives in jyotish_ug, imported by jyotish.engine
  packages/jyotish-core is nearly empty; do not put new code only there
    unless you also re-export from jyotish/.

refresh=true
  UG education: IGNORED when cached. Delete first.
  PUC / career / business profile endpoints: refresh=true DOES recompute
  (see each *_service.py). Do not assume they share UG's freeze policy.

LLM providers are not interchangeable
  UG field report: Gemini/OpenAI/Anthropic via jyotish/llm.py
  Career AD HTML: OpenAI/Anthropic only (llm_narrative_builder)
  PUC narrative: stream_narrative.py via same llm stack + consent flags
  API always stamps consent; missing keys still produce fallbacks.

Dynamo 400KB
  Never store full method_breakdown / HTML in JyotishEducationAnalysis.
  Profiles already chunk. If a new analysis is large, either gzip like
  education_repository or a new table. Do not stuff it into the header item.

ChartSession.chartId
  For profiles this IS profile_id. UG cache APIs depend on that.
  Legacy local charts use local-{timestamp} or saved chart_id from the
  old /api/users/{user_id}/charts table.

Ayanamsa split brain
  Drawing default LAHIRI (PyJHora API).
  Scoring engines KP_KRISHNAMURTI via consolidated export + llm_policy.py.
  If you "fix" one without the other you will desync charts vs reports.
  Profile form offers LAHIRI / KP / RAMAN for the drawing layer.

Score-neutral modules (must not change final_score)
  shadow_scoring.py, composite_v2.py, audit_ledgers.py, provenance.py,
  ontology_kg.py attach_graph_diagnostics, defensibility.py,
  run_manifest.py, many decision_axes attachments unless comments say
  they now apply a bounded penalty (decision_axes D1/D10 penalty IS
  live after apply_release_4_7 — read the comment in run_engine).

Thread pool
  UG/career/business profile endpoints use FastAPI run_in_threadpool
  because engines are sync and slow (30-60s with LLM).

PyJHora init is process-global
  init_jhora() is once-per-process. Node mode is flipped per request in
  _compute_birth_chart if use_true_nodes. Be careful with concurrent
  true-node vs mean-node requests on one worker.

HTML vs JSON reports
  Web app renders React from JSON.
  CLI still writes HTML under educational_records/ (gitignored).
  Do not add server-side HTML for UG as the web contract.

Education tab default
  Ages 15, 16, 17 -> PUC else UG. Keep Python runner and
  frontend/src/lib/education-report/tab-defaults.ts in sync.

Coming-soon pages
  panchanga, reports, (AI unless flag): UI stubs. Backend data may already
  exist. Prefer wiring existing session payloads over new engines.

Unused / decoupled
  Planetary transits route intentionally omitted (api/main.py comment).
  frontend/src/lib/prompts/fieldDetermination.ts is a leftover prompt string;
  live prompts are in jyotish/llm.py and career_field_report_v2.py.
  frontend/src/lib/api/example.functions.ts is a TanStack Start sample.
  frontend/src/routes/astro.code-workspace should not live in routes/.
  Field_Determination/de421.bsp duplicate of root ephemeris — do not
  commit; use scripts/download_de421.py.

Version stamps
  Bump jyotish/__init__.py __version__ AND payload.ENGINE_VERSION together.
  Business has its own RULE_PACK_VERSION / MODEL_STATUS in
  business_determination.

Naming in the UI vs code
  "Job Timeline" UI = career-timeline engine
  "UG" = career field determination (not only undergrad students)
  "KN Rao" page = Jaimini payload from /api/jaimini
  "Parashari Strength" = ashtakavarga + shadbala

27. HOW TO ADD A NEW ENGINE FEATURE (CHECKLIST)
================================================================================

1. Decide the surface: drawing-only (api/extended.py) vs scoring engine
   (jyotish / Job_Career / Business / jyotish_puc).
2. If it needs natal facts, add fields to NatalPayloadV2 (payload.py) and
   populate them in engine_io.parse_json_payload. Add tests.
3. If it is a new HTTP capability:
     - Pydantic models in api/schemas/<domain>.py
     - Adapter api/<domain>.py  (no Dynamo here)
     - Optional cache service api/<domain>_service.py
     - Register routes in api/main.py
     - Frontend types in lib/pyjhora/types.ts
     - Client method in lib/pyjhora/client.ts and/or lib/profiles/client.ts
     - Route + section component
     - NAV + PROTECTED_ROUTES
     - Persist: either profiles_repository chunk or a dedicated table
4. If LLM text is involved: gate on consent, never score, always fallback.
5. If registry-related: update JSON + affinity + ontology + validator.
6. Add tests beside the owning package.
7. Update this knowledge base's routing row.

================================================================================
28. HOW TO FIX A BUG (CHECKLIST)
================================================================================

1. Reproduce at the UI route. Note whether a profile is loaded (chartId).
2. If 401/403: auth. If 503: Dynamo env. If 422: schema/career_context.
   If 502: engine exception (check uvicorn traceback).
3. For wrong numbers: identify drawing vs scoring. Drawing bugs live in
   api/main.py / extended.py / PyJHora. Scoring bugs live in engine.py /
   field_methods / boosts / ranking_policy / domain package.
4. For wrong text: LLM files or React report components. Cached UG text
   will not change until DELETE analysis.
5. For missing UI data that API already returns: hydrate path
   (restore-session / ChartSession field names) is the usual gap.
6. Search function names from this document rather than inventing a new
   module. Many "missing" features already exist under a different name.
