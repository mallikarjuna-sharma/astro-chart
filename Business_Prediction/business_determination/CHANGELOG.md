# Business Determination Engine -- Audit / Remediation History

This file holds the full, version-by-version remediation history that used to be embedded directly inside `business_determination/constants.py`'s `EVIDENCE_BASIS` string constant (over 1000 lines of narrative changelog entries). It was extracted out as part of engineering-audit item #8 ("1000+ line changelog embedded in constants.py") -- `EVIDENCE_BASIS` at runtime now only carries a concise active-methodology summary plus the maturity statement; this file is the historical record for anyone auditing why a given rule exists in its current form.

Entries are in chronological order (v13 is the oldest fix recorded; the most recent is at the bottom, and constants.py's RULE_PACK_VERSION reflects the current version).

---

## -- FIXED_v13: significator strength ceiling (_POSITIVE_CEILING) rescaled 256.0 -> 160.0, anchored to an empirically-constructed maximal-plausible reference chart instead of the sum of every individual rule's independently-unreachable maximum, which was silently compressing genuinely strong real charts into the 20s-30s (user-reported wrong output on a real chart with a planet ruling both H7 and H10 in strong dignity)

## -- FIXED_v14 (deep astrological audit of the mode gate, same real chart): (1) replaced FOUR different per-mode ceilings with ONE SHARED ceiling across employment/business/independent/family, so raw evidence is directly comparable instead of comparing percentages of differently-constructed, non-equivalent maxima; (2) Sun-in-H10 no longer routed exclusively to employment -- also credited to independent/business leadership, since Sun signifies authority/visibility generally, not employment specifically; (3) added the H7-H10 sambandha and H10-lord-in-own-house findings to the mode gate itself (previously visible only in the significator ledger, never scored in the decision layer); (4) added H11-lord-in-trikona as a business finding, parallel to the existing H6-lord-in-kendra/trikona employment finding; (5) D10-native H6 malefic occupancy now softened when standalone (parity with the KP H6 softening), and D10-H10 benefic occupancy now scored (previously only H2/H7/H11 checked, an asymmetry against the full-dusthana negative scan); (6) added a static, chart-level KP H7-cusp-sub-lord signification bias and Amatyakaraka house-lordship check to the mode gate -- previously KP/Jaimini evidence only ever influenced timed windows, never the static proceed/deny decision, which could produce an internally contradictory report (static: do not proceed; timed windows: KP/Jaimini favorable); (7) fixed a misleading AD-lord evidence string that said 'rules H2/H7/H11' even when the lord ruled only ONE of those houses.

## -- FIXED_v15 (provenance/reporting defect, user-caught): method_status previously collapsed each corroboration method into ONE status field inferred only from TIMED-WINDOW evidence text -- D10 could report PRESENT_NOT_TRIGGERED even when D10 evidence had materially driven the static significator ledger and mode gate, because it never happened to ALSO fire inside a timed window on that chart.
